Verified boot recomputes ro.boot.vbmeta.digest and .size from the real AVB chain on-device. Boot-state normalizes the lock-state/warranty/debuggable props and, where the kernel exposes it, the raw /proc/cmdline + /proc/bootconfig boot-state to match — only ever changing a prop that already exists, and skipping procfs if the kernel has no nomount knobs. Kernel uname keeps the running kernel's base and swaps the tail + build date so uname matches the ROM; blank keeps the current values, or paste them from a stock device. Hiding

Cloak (maps / fd)

—›

Hide selected Xposed/LSPosed module APKs from every process's /proc/<pid>/maps and /proc/<pid>/fd via the kernel pathhide interface — applied live and re-applied on boot.

Hidden paths

—›

Make a stock ROM file disappear — for paths that are themselves the tell, like install-recovery.sh. Saved to a list and re-applied on every boot, in the same pass as the injections. This is not a module: nothing is installed and nothing is mounted. Scan walks the ROM for files only a root setup leaves behind; on a mountless install it usually finds nothing, which is the correct answer — nothing is written to /system, so there is nothing on it to hide.

Foreign mounts

—›

Mounts that another module laid over the ROM. Every one is readable by any app in /proc/<pid>/mountinfo, which is the whole thing the mountless posture denies. Absorb re-serves each as a Prism injection and drops the mount; it also runs at every boot. A hook framework (Zygisk/Xposed) is deliberately left alone — breaking one only surfaces later, during dexopt.

Per-UID hiding

—›
Curated list of root/environment detectors, including globs that keep matching when a detector is repackaged under a new name.
What hiding covers

Shows the listed app the stock filesystem — no injected files, no whiteouts, stock directory metadata. One entry covers the app in every user, work profile and clone (matching is on the appid), and its SDK-sandbox process too. Use a package name: it survives a reinstall, a raw UID doesn't. Root is unaffected, and so is su — that's sucompat, not the engine. Doesn't cover SELinux-policy detection, or anything a system service reads on the app's behalf (PackageManager still parses the injected APK).

A glob covers a moving target: *.duckdetector, me.garfieldhan.* or *chunqiu* re-match on every apply, so a detector that reinstalls under a new package name stays hidden. Anchors go at the ends only, and a glob needs at least four literal characters.

Why this trades one tell for another

An isolated process gets a pool UID that says nothing about which app spawned it, so hiding from a listed app can only mean hiding from every isolated process. That closes the hole where a hidden app farms its probing out to an isolated helper — but while it's on, an app that isn't hidden can spot the injection by diffing its own view against its own isolated child's. Both pools are hidden by default; narrow it here if you'd rather not arm that comparison. No effect unless at least one app is hidden.
