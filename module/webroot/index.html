Per-UID hiding

Scan finds what is installed now; globs keep matching what installs later.
What hiding covers

Shows the listed app the stock filesystem - no injected files, no hidden paths. One entry covers the app in every user, work profile and clone. Use a package name: it survives a reinstall, a raw UID doesn't. Root and su are unaffected, and so is anything a system service reads on the app's behalf.

Scan lists apps installed here worth hiding from and says why - nothing is hidden until you pick it. It cannot cover what is not installed yet.

A glob covers a moving target: *.duckdetector, me.garfieldhan.* or *chunqiu* re-match on every apply, so a detector that reinstalls under a new package name stays hidden. Anchors go at the ends only, and a glob needs at least four literal characters.

Why this trades one tell for another

An isolated process's UID says nothing about which app started it, so hiding from one app means hiding from every isolated process. That closes the hole where a hidden app probes through a helper - but while it's on, an app that isn't hidden can spot the difference between its own view and its helper's. Both pools are covered by default.

Hidden paths

- ›

Make a stock ROM file disappear - for paths that are themselves the tell, like install-recovery.sh. The list is saved and re-applied on every boot, in the same pass as the injections. Nothing is installed and nothing is mounted. Scan walks the ROM for files only a root setup leaves behind; on a mountless install it usually finds nothing, which is the correct answer - nothing is written to /system, so there is nothing on it to hide.

Absorbable mounts

- ›

A module that bind-mounts its own content leaves a mount any scanner can read. Absorbing re-serves it as a Prism injection and unmounts the original - same content, no mount.

This runs by itself: once after every module's boot script, once more 45s later, and - only with the my_hookless trial on - before zygote too. The chip is what is left after that. The buttons are for a mount that shows up later, so you need not reboot. Scan only reports.

A Zygisk/Xposed hook framework's binds are never taken over: a broken hook fails at the next app install, not at boot.

Developer tools

Snapshot freezes today’s fingerprint as the baseline, replacing any earlier one. Verify diffs the live system against it. Export writes a folder under /sdcard/Download with the check report, the fingerprint, the live rules and the mount table - attach the whole folder to a bug report. Anything naming the apps you hide is left out of a shared destination, the boot log included; the folder says so and tells you how to get the full set privately.
